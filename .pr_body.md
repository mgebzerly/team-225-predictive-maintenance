## Summary

Implements Task 1 (Data + SQL) for the Team 225 AI4I 2020 Predictive Maintenance project.

**Deliverables added:**

- `data/raw/ai4i2020.csv` — AI4I 2020 dataset (10,000 rows, 14 columns), verified correct
- `data/cleaned/ai4i2020_cleaned.csv` — cleaned version: snake_case column names, derived columns (temp_diff_k, power_kw, wear_rate)
- `data/features/ai4i2020_features.csv` — feature-engineered dataset: rolling stats, lag features, binned features, one-hot encoding, interaction terms
- `data/ai4i2020.db` — SQLite database with:
  - `machines` (10,000 rows)
  - `sensor_readings` (10,000 rows + generated columns for temp_diff_k, power_kw, temp_ratio, torque_per_rpm)
  - `failure_events` (355 rows, one per failure type per failure event)
  - 3 views: `failure_summary_per_machine`, `sensor_stats_per_type`, `pre_failure_windows`
- `sql/schema.sql` — relational schema (CREATE TABLE + indexes + views)
- `sql/queries.sql` — **18 analytical queries**, all verified executable:
  - JOINs (query 02, 08, 10, 13)
  - CTEs (queries 03, 04, 05, 08, 09, 10, 11, 12, 13, 14, 15, 16, 17, 18)
  - Window functions (queries 04, 05, 06, 07, 11, 18 — including ROW_NUMBER, RANK, DENSE_RANK, NTILE, LAG, LEAD, SUM/OLAP, FIRST/LAST_VALUE)
  - Exceeds the minimum requirement of 10 queries
- `sql/run_queries.py` — query runner utility
- `src/data_pipeline.py` — reproducible raw→cleaned→features pipeline
- `src/load_to_sql.py` — loads cleaned data into SQLite (re-runnable, idempotent)
- `reports/data_dictionary.md` — data dictionary: raw/cleaned/feature columns, failure type definitions, data quality notes

## Notes

- Each product_id has exactly one reading (10,000 unique machines). UDI provides the sequence order. Window functions partitioned by product_id collapse to single rows; queries use UDI ordering or partition by type instead.
- `src/load_to_sql.py` is re-runnable: it drops and recreates tables/views on each run. Safe to re-run after any pipeline changes.
